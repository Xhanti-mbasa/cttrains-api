# Developer controls and updates (1.14)

In Settings, tap the CT Trains for Android version label seven times in quick succession. Enter a single-use invitation or your reusable owner credential. Access is checked by the separate service; there is no master bypass or verifier list in the APK. The service must be deployed before codes work. Keep your owner credential private: it can issue access and change notices for users, unlike an ordinary invitation.

Tester access: screen availability switches, existing feature toggles, local memory/storage diagnostics, allowlisted developer events, reviewed diagnostic-file export, timetable cache cleanup and stopping active test sessions. These tools do not grant root or bypass Android permissions. Screen switches are device-local and reset when access is locked, expired or cannot be verified. Persistent feature preferences remain the ordinary user preferences. A screen toggle is a UI test control, not a promise to disable every underlying worker; use the feature's own opt-out and Stop active test sessions for background work.

Owner access additionally creates batches of 16 random invitations, rotates the owner credential, shows access IDs/status and server audit, revokes individual or all tester access, and publishes expiring notices for selected installed versionCode ranges and optional GitHub release tags. The notice form has a review step. Stable releases and the Lab edition compile this maintenance capability off. Maintenance is a temporary test-build gate, off by default, with Settings/backups/updates left available. It cannot affect already installed old builds that lack the feature, stop offline devices, silently install software or delete data. Retire maintenance before broad public rollout as described in control-service/README.md.

On each foreground visit, GitHub checks run at most once per 15 minutes to limit network traffic. A normal update appears as a dismissible banner once per available version. A newer release can trigger a new banner. Security notices recur per foreground visit for affected installed version codes while their server policy is unexpired. A targeted release must still pass the normal updater's package, signer, SDK, version, size and checksum checks. The first-install snackbar explains that downloads happen first, Android confirms installation and the app may need reopening. Nothing forces the app closed or installs silently.

CT Trains Lab is reserved for Claude's redesigned edition. A build with CTTRAINS_EXPERIMENTAL=true uses its own application ID and app label; the redesigned screens and experimental release channel still need to be implemented by Claude. No duplicate stock APK is presented as a completed redesign. See CLAUDE-EXPERIMENTAL-REDESIGN.md for the complete handoff.
